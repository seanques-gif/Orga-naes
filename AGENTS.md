# AGENTS.md — Orga-naes

Read this first. It keeps every agent session on the rails.

## Golden rules

1. **Source of truth is `src/`.** Edit files under `src/` only.
2. **Never hand-edit `Orga-naes.html`.** It is generated by `node build.mjs`.
3. After ANY change to `src/`, run: `npm run build`
4. Then verify: `npm test` (both must stay green).
5. The shipped artifact must remain **one file** (`Orga-naes.html`), **vanilla JS**,
   with **no framework and no runtime build step**. Do not introduce either.
6. Do not change the data model, storage keys, export/import formats, Firebase sync,
   the nested-subtask engine, or PWA behavior unless explicitly asked.

## Commands

- `npm run build` — regenerate `Orga-naes.html` from `src/` (+ refresh `Orga-naes.html.sha256`)
- `npm test` — design-token guard + date utils (must be green before commit)
- `npm run verify` — determinism gate (zero-write check: pin = artifact = rebuild from src/) then test

## Layout

```
src/
  template.html     HTML shell with 3 injection tokens (css main, css print, script)
  order.json        exact concatenation order for css + js fragments
  styles/           *.css   (01..11 main, 90 print)  — pure concatenation, any cut is safe
  js/               *.js    (01..45) — fragments of ONE IIFE, concatenated in order
Orga-naes.html      generated build output (committed; never edit)
build.mjs           the build (zero dependencies, Node only)
tests/*.test.mjs    guards (read the built Orga-naes.html)
```

## How the build works

`build.mjs` concatenates the CSS and JS fragments in the order listed in
`src/order.json`, injects them into `src/template.html`, and writes `Orga-naes.html`.
The JS fragments are all inside a single `(function(){ ... })()` IIFE, so they share
one scope and MUST stay in order. Builds are byte-deterministic: a no-op change must
reproduce `Orga-naes.html` exactly — `Orga-naes.html.sha256` pins the bytes and
`npm run verify` fails if the committed artifact or src/ drifts from the pin.

## Editing conventions

- Keep the `// SECTION:` / `// SUBSECTION:` markers; they map the file to fragments.
- Add a new JS area as a new numbered file and register it in `src/order.json`.
- Keep the One-Root (`--font-size-base`), Tint-Through-Token (`color-mix`), and
  White-Pair (`--accent-contrast`) rules. `npm test` enforces them.
- The standalone PDF export (`src/js/` reports module) intentionally uses literal px
  and non-token colors — it is a separate document with no `#pf-root`.

## Do NOT

- Run any old one-time extraction tooling against `Orga-naes.html` (it would clobber `src/`).
- Commit with `Orga-naes.html` out of sync with `src/` (always `npm run build` first).
- Break mobile/desktop parity or offline behavior for a visual change.
